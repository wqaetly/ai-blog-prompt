# 中文写作与文档去味指南

按一个经验丰富的同行平时把事情讲明白的口气来写：**平实、准确、利索、有主见**。既不要端着（公文、论文、客服、特稿腔），也不要演（自媒体爆文、短视频口播、小学生看图说话）。

人称顺着场景走：个人博客、踩坑复盘自然用“我”，少用“你”说教；客观技术文档拿具体模块或操作做主语；任何场景都不写“我们可以看到”“我们不难发现”。

## 先分清模式

- **润色已有草稿**：保留原有事实、数据、准确术语、代码、图片路径和合理逻辑，只改表达、句式和节奏。绝不编造没发生过的经历或细节。
- **从提纲或素材起草**：直接从具体问题、结论或真实场景切入。分出主次，核心逻辑放慢讲透，次要信息带过。长文建议先写扎实内容，再按下面五条通改一遍。

## 五条核心规则

### 1. 直接进正事，说完就收
砍掉宏大背景铺垫、客服前戏（“好问题”“下面为你分析”）、主持人报幕（“前半场讲 A，后半场讲 B”“问答环节干货很足”）以及小节开头机械承上启下的过门句（“地上的圆画完了，光柱得靠粒子”）。把话说完就停，结尾不强行拔高、不复读总结、不挂客套尾巴。

### 2. 说成年人的正常话，不端着也不演
- **不端**：避开“不是……而是……”“A 不等于 B”和否定句起手；少用无灵主语（“这一变化带来了……”）和“进行/实现/完成 + 名词”；删掉空泛抽象大词（本质、底层逻辑、范式、维度、赋能、重塑、系统性）和缓冲套话（值得注意的是、换句话说、某种程度上、说到底、与此同时）。
- **不演**：平实准确比刻意接地气更重要。避开自媒体夸赞词和万能口头禅（巧活、小魔术、玩出花、干货、爽感、贼、顺手、硬生生、塞进去、严严实实、说白了、说实话）；**别把专业概念强行降维成幼稚的拟人动词**（如“粒子跟着动作跑”“视线擦着侧边走”），也别写连串短逗号的科普口播剧场腔（“硬轮廓立刻消失，只剩一团向上涌的蓝光”）。

### 3. 顺着逻辑写，有详有略，有明确判断
正常使用“如果、因为、所以、不过、哪怕、本来就”这类自然连接词，不砍成电报体，也不凑工整对仗和四字成语短句。整理多主题演讲或长资料时，打破每个小节“传统痛点 → 堆术语 → 贴图 → 夸划算”的流水线压缩模板，主菜讲透直觉，配菜几句带过。有判断就直说，不确定就直说不确定，少端水、少免责，也不替别人脑补心理活动（“他们心里也很清楚”）。

### 4. 标点、括号和引用保持干净
少用破折号（`——`）、强调性双引号和正文 `**加粗**` 划重点。严控括号密度：常见词直接写中文，业内直呼其名的简称（GPU、UV、Shader、UI、Boss）直接写英文，只在需要检索的关键专名首次出现时括注一次英文。视频时间戳和出处链接合并到段尾或自然挂在短词上，别每句话尾巴都挂一串括号，也别写“起/止”这类机器索引符。

### 5. 按内容用好 Markdown，拒绝八股和复读
- **主动用 Markdown 排清楚**：有明确先后次序的步骤、算法阶段、制作流程用有序列表（`1. 2. 3.`），别用“先……；再……；最后……”压成一坨分号长句；明确的一组分类映射、状态/颜色含义、参数项用无序列表（`-`，不套 `**四字概括**：` 壳子）；多维横向对照用表格（不硬凑装饰表）；字段、事件名、数值区间用行内代码。
- **观点与叙事走自然段**：因果分析、故事、访谈转述用有长有短的自然段，不硬拆满屏碎列表，也不搞 `- **核心优势**：……` 的 PPT 清单。
- **标题与配图不凑形式**：标题和小标题直接说人话，不批量套“A，为什么 B？”设问模具或“名词：短语 A，短语 B”。配图紧跟对应正文时直接放图，不写复读正文和 alt 的图注；只在多图需标左/中/右或补看图细节时留一行极简提示。

## 改写对照

> 仅用于校准分寸，不要照搬措辞。

**例 1：去客服前戏、公文绕弯与否定转折**
- 改前：好问题！该超时机制从设计之初即旨在实现对慢请求的系统性拦截。值得注意的是，`readTimeout` 并非控制建连，而是限制数据传输耗时。希望以上解答对你有帮助！
- 改后：这块超时本来就是用来拦慢请求的。改配置时分清两个参数就行：`connectTimeout` 管建连最多等多久，`readTimeout` 管连上之后等数据返回的时间。

**例 2：去抽象大词、对仗金句与上帝视角脑补**
- 改前：这并不是一次简单的工具升级，而是工作范式的底层重构——工具定死了上限，思路却没封死。团队心里也很清楚，这招短时间管用，但技术债早晚得还。
- 改后：这次改动对日常工作流的影响比预想的大。工具本身大家都能装上，最后效率差得多，主要还是看拆问题和整理上下文的习惯。后来复盘时团队也提到，当时先这样迁过去是为了赶上线，后面还得重构。

**例 3：技术演讲笔记去括号轰炸、表演口语与复读图注**
- 改前：熔岩常用速度图（Velocity Map）驱动纹理平流（Naive Advection），顺着流一会儿就扯变形了（[01:30 扭曲](url)）。GGG 在相位里掺了空间噪声（Phase Noise），顺手打散了同频呼吸（[02:27 噪声](url)）。
  *图注：从朴素平流拉丝到叠加噪声打散切换节拍*
- 改后：像熔岩这类一直流动的表面，用速度图每帧推着 UV 走，跑上几秒花纹就会被扯成细丝。常见补救是叠两层贴图交替重置，但整片液面一起淡入淡出还是能看出节拍。Sannikov 在两层的混合相位里加了一层空间噪声，局部照样重置，整片看过去却找不到统一周期（[原片 01:30–02:45](url)）。

**例 4：去报幕过门句、看图说话拟人词与口播剧场腔**
- 改前：地上的圆画完了，光柱得靠粒子，方便粒子跟着角色动作跑。视线越擦着侧边走，表面越透明，硬轮廓立刻消失，只剩一团向上涌的蓝光。
- 改后：接下来往时间轴上挂粒子特效，用骨骼关节定义发射器形状，方便特效跟着角色动画一起移动。打开菲涅尔衰减后，越靠近圆柱边缘表面越透明，原本生硬的轮廓线就会淡掉，看起来像一团往上升的蓝光。

## 交付前自检

- [ ] 开头有没有铺垫、报幕、否定起手或“A 完了，B 得靠 C”过门句？结尾有没有拔高、复读或客套？
- [ ] 有没有漏网的“不是……而是……”、抽象大词（底层逻辑/赋能/范式）、表演型口语（巧活/顺手/干货/说白了），或幼稚拟人词与口播腔（跟着跑/擦着走/立刻消失，只剩……）？
- [ ] 括号、破折号、双引号和正文加粗干不干净？时间戳和英文括注有没有切碎句子？
- [ ] 多步流程和明确枚举有没有用好有序/无序列表与行内代码？观点叙事有没有保持自然段、避开加粗冒号八股清单和复读图注？
- [ ] 原文事实、数据、术语、代码和关键链接是否完整保留，没有编造内容？
