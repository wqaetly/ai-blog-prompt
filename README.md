# ai-blog-prompt

AI 写中文博客或长文时，很容易带出一股机器味。这个仓库把去味提示词拆成两部分，按场景选用：

- **全局提示词**（下文代码块）：精简、无示例，适合放进对话开头、Custom Instructions，或常驻在 `AGENTS.md` / `CLAUDE.md` 里，少占上下文，也不容易干扰写代码等非写作任务。
- **Agent Skill**（[skills/humanize-blog/SKILL.md](skills/humanize-blog/SKILL.md)）：面向支持 Skills 的 Agent 按需加载，包含“写初稿 / 润色改稿”双模式、完整细则、少量改写对照和交付前自检。

## 一、全局提示词

直接复制下面这段即可：

```text
写中文文章或润色文字时，按普通人平时跟朋友聊事情的口气来写，偏口语化一点，不要太官方，也不要太极客。尽量用第一人称“我”自然转述，少用“你、你们”，也不要写成论文或公文里的“我们可以看到”“我们不难发现”。

写作和改写时注意避开这些机器味：
- 少用排比和套路转折，像“不是……而是……”“并非……而是……”“不是……更像是……”“A 不等于 B”尽量别用；也不要用否定句开头，直接把真正想说的话写出来。
- 口语化别用力过猛，不要写成公众号爆文或短视频解说，少用夸张动词和叠词（如“塞进去”“严严实实”“原封不动”“彻底撑住”），用准确的普通表达就好；同时少用“底层逻辑、范式、赋能、重塑”等抽象大词，以及“值得注意的是、换句话说、某种程度上”这类填充套话。
- 正常使用“如果、因为、所以、不过”等连接词，别为了短促硬砍连词写成电报体，也不要连写结构对称、末尾挂着四字成语的短句；不凑工整对仗和押韵金句，每段说完就结束，不强行拔高或模板化收尾。
- 克制使用破折号（——）、括号里的俏皮话补充，以及给普通词乱加双引号表强调。
- 语气前后一致，别前半句油滑吐槽、后半句突然文艺抒情；别用上帝视角脑补别人心理（如“他们心里也很清楚”），客观写对方说了什么、做了什么就行，引用原话直接加引号。
- 别为了显严谨频繁塞免责声明（有必要交代前提顺手带一句就行），也别动不动“一方面……另一方面……”端水；改写时保留原文观点、事实和专业术语，不编造没发生过的个人经历。
- 直接从具体问题或现象切入，省掉宏大背景开场；小标题直接说人话，别用“名词：短语 A，短语 B”；重点展开、次要带过，别动不动搞“加粗小标题 + 冒号”的清单体或强凑三点并列。
```

## 二、Agent Skill（按需加载）

完整 Skill 位于 [skills/humanize-blog/SKILL.md](skills/humanize-blog/SKILL.md)，遵循主流 Agent Skills 目录格式（`skills/<name>/SKILL.md`）。

### 使用方式

- 将 `skills/humanize-blog` 目录复制到你所用 Agent 的 skills 目录（例如项目或用户目录下的 `.claude/skills/`、`.agents/skills/`、`~/.codex/skills/` 等），在写博客、长文或要求“去 AI 味/润色”时会自动按需加载。
- 也可以在需要时直接让 Agent 读取 `skills/humanize-blog/SKILL.md` 后再动笔。

### 实操建议：两步法比一步到位更稳

如果文章偏长或技术细节比较多，建议拆成两轮：

1. **先写内容**：这一步不贴风格禁令，先把观点、事实、论据和代码/案例写扎实。
2. **再去味润色**：调用 `humanize-blog` Skill（或贴入全局提示词）做第二轮改写，只调表达、句式和节奏。
